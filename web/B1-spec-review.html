B1 — Tail-quantile ("all-fire" / "no-fire") reporting — Design Spec

  • Date: 2026-07-01
  • Addendum item: B1 (shipped v1.1 feature)
  • Status: approved for implementation (owner brought it into scope 2026-07-01)
  • Cadence: built one piece at a time, each with a tiny hand-checkable result, stop and wait for OK. Source-tag everything ([PAPER]/[PUBLISHED]/[RECOMMENDATION]).

1. Purpose (plain language)

The report currently gives the average breaking point and the spread. B1 adds the two numbers a practitioner usually actually wants — the ends of the distribution:

  • All-fire level — high enough that ~99.9% of items break ("count on it working").
  • No-fire level — low enough that ~99.9% of items survive ("count on it being safe").

Each is printed with a ± confidence figure and a short caveat, and returned in the result struct.

Paper anchor [PAPER]: Neyer (1994) defines the all-fire level as "the level of shock necessary to cause 99.9% of the specimens to fire. (Some designers seek the 99.99% or 99.9999% levels.)" — so the 99.9% default and the adjustable dial are straight from the paper.

2. Design decisions (settled in brainstorming, 2026-07-01)

  1. Report both ends (all-fire + no-fire). Nearly free — the same formula with a sign flip — and it makes the C4 "tail = design allowable, opposite tail" point concrete. [RECOMMENDATION]
  2. Strictness is an adjustable dial, default 99.9%. One tagged constant in settings.m. [PAPER for the definition; RECOMMENDATION for the 99.9% default]
  3. The "fraction → level" bell-curve step lives in shape_model (#1), the shape's one home — added additively, so nothing the existing tests rely on changes. This honours the "shape lives in one file" rule while still meeting the addendum's real intent ("don't disturb the Table-1 core"). [RECOMMENDATION]

3. Components

3.1 src/math/shape_model.m (#1) — add an inverse

Add a second call form; the existing forward form is untouched.

  • Forward (unchanged): s = shape_model(x, mu, sigma) → struct {z,phi,Phi,Q,p}.
  • Inverse (new): z = shape_model(p, 'quantile') → the standardised level z such that Phi(z) = p, computed as z = sqrt(2) * erfinv(2*p - 1).
  • Vectorised over p. Returns a plain numeric array (not a struct).
  • Validates 0 < p < 1 (finite); errors otherwise under shape_model:badProb.
  • Dispatch: inverse mode iff called with exactly 2 args and the 2nd is the char string 'quantile'. Any 3-numeric-arg call is the forward path as before.
  • Why erfinv: it is a base function in both Octave and real MATLAB — no toolbox. It is the exact inverse of the erfc the forward path already uses, so the standard-normal maths stays entirely inside this one file. [RECOMMENDATION]

3.2 config/settings.m — one new constant

s.tail_fraction = 0.999;   % all-fire fires this fraction; no-fire = survive this fraction.
                           % PAPER (all-fire ~99.9% definition); 0.999 default RECOMMENDATION.

3.3 src/workflow/report.m (#9) — compute and print the two levels

Runs only when overlap exists (report already gates on this). Reuses the information matrix report already computes at the final estimate (I00, I01, I11, detI).

  • k = shape_model(cfg.tail_fraction, 'quantile'); % e.g. 3.0902 for 0.999
  • Levels:
  • all_fire = mu + k*sigma
  • no_fire = mu - k*sigma
  • Uncertainty (delta method) [PAPER App.A Eqs.5-6 + 2x2 inverse]:
  • var_mu = I11/detI, var_sigma = I00/detI, cov = -I01/detI
  • var_all = var_mu + k^2*var_sigma + 2*k*cov
  • var_no = var_mu + k^2*var_sigma - 2*k*cov
  • se_all = sqrt(max(var_all,0)), se_no = sqrt(max(var_no,0)) (the quadratic form is >=0 for a valid covariance matrix; max(...,0) guards only against tiny numerical negatives.)
  • New result fields: tail_fraction, tail_k, all_fire, se_all_fire, no_fire, se_no_fire.
  • Printed block (after the existing average/spread lines): All-fire (99.9% break) : 8.60 +/- <se> No-fire (99.9% survive): 2.18 +/- <se> Note: a D-optimal test is not tuned for the far tails, so these carry wider uncertainty than a purpose-built tail study would. [see docs C4/D] The "99.9%" text is derived from cfg.tail_fraction, not hard-coded.

3.4 Tests

  • tests/test_shape_model.m (extend): the inverse.
  • shape_model(0.999,'quantile') ≈ 3.0902 (to 1e-4).
  • Round-trip: Phi(shape_model(p,'quantile')) == p for p in {0.001,0.5,0.9,0.999}.
  • Symmetry: shape_model(0.001,'quantile') ≈ -3.0902; shape_model(0.5,'quantile') ≈ 0.
  • Errors on p<=0, p>=1, non-finite.
  • tests/test_report.m (extend): the tail levels, on the Table 1 run.
  • Assert all_fire == mu + k*sigma and no_fire == mu - k*sigma, with k recomputed independently in the test via sqrt(2)*erfinv(2*0.999-1).
  • Hand-check anchor to the paper's own final fit (mu=5.39, sigma=1.04): all_fire ≈ 8.60, no_fire ≈ 2.18 (to 2 decimals).
  • Assert se_all_fire/se_no_fire match an independent delta-method recomputation from the info matrix (to ~1e-6).
  • tests/run_all_tests.m: no new files to register (tests extended in place); fix the stale final-summary line that says "9 watchdogs" so the count reflects the full suite (worker watchdogs + addendum A1/A2/A4 + A3 grid-stability + acceptance).

4. Testing strategy against the paper (how we validate)

The paper does not print a worked all-fire number for the Table 1 example, so B1 is validated by:

  1. Hand-check (primary): the paper's own final fit (5.39, 1.04) and its 99.9% definition force all-fire ≈ 8.60, no-fire ≈ 2.18. The test asserts this.
  2. Uncertainty sanity band: the paper's asymptotic formulas var(mu)=sigma^2/(0.392 N), var(sigma)=sigma^2/(0.507 N) give a ballpark the ± figure should sit near (not an exact gate — the real test isn't all at ±1.138σ).
  3. Optional second opinion: gonogo (R) / senpy (Python) on the same sequence.

5. Acceptance criteria

  • The Table 1 acceptance gate still passes exactly (5.39 / 1.04, all 20 levels, all running estimates) — proof the addition disturbed nothing.
  • New inverse checks pass; new tail checks pass, matching the 8.60 / 2.18 hand-calc to 2 decimals and the delta-method uncertainty to ~1e-6.
  • Full suite green in Octave 11.3.0 and MATLAB R2022b on the laptop.
  • Later, on the college PC: one confirmation run in real MATLAB (erfinv is base there too, so expected to be a formality).

6. Out of scope (YAGNI)

No plotting; no reporting several fractions at once; no separate "tail report" mode; no change to the selection logic (#3) or the brain (#6); no change to any Table-1 behaviour. The two swap-points stay sacred (#1 gains an additive inverse only).

7. MATLAB/Octave compatibility

erfinv is a base function in both. No toolboxes introduced. Consistent with the project's toolbox-free rule.
