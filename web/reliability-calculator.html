The reliability calculator

Once a test has finished, you have a fitted bell curve — an average breaking height and a spread. The reliability calculator (reliability_query) turns that curve into the answers you actually want to quote: "at what height is it safe?", "how reliable is this height?", and "how many parts would I need to prove it?" This page explains the idea and every mode in plain language.

The one idea: three numbers, give two, get the third

Every reliability question is really about three linked numbers:

Confidence is your honesty dial — it is not the same as reliability. Reliability is "what fraction of parts behave"; confidence is "how sure we are of that, given we only tested a few dozen parts." A conservative bound is always at 95% (or whatever you set), so the number you quote already has the margin baked in.

Start it after any finished run: 
reliability_query(result)
You get a small menu — pick a mode, choose break or survive, then a reliability and a confidence. Every mode below can also be called directly in one line (shown under each).

Break or survive — pick the tail you care about

Every question comes in two flavours, because your parts have two edges:

TailQuestion it answersThe number
break (all-fire) How high must I drop from so almost every part breaks? an upper height
survive (no-fire) How low must I stay so almost no part breaks? a lower height

Mode A — "I have a target reliability, give me the height"

You know how reliable you need it (say 1 in 1,000) and want the height that delivers it, with margin. In the menu this is [1] Safe height for a reliability. In one line:

reliability_query(result, 'survive', 'height_for', 0.999, 0.95)

Reads as: "for the survive edge, find the height at which 99.9% of parts survive, and give me the conservative bound at 95% confidence." You get back a plain-language line like:

95% confident that 99.9% of parts survive below 38.42 mm.

Because it's conservative, the reported safe height is a little lower than the raw best-guess height — that gap is the 95%-confidence margin. Ask for higher confidence and the safe height drops further; ask for more reliability (1 in 10,000) and it drops further still.

Mode B — "I'm stuck with a height, how reliable is it?"

Sometimes the height is fixed for you (a drawer sill, a shelf, a spec) and you just want to know how safe it is. In the menu this is [2] Reliability at a height. In one line:

reliability_query(result, 'survive', 'reliability_at', 35, 0.95)

Reads as: "at 35 mm, on the survive edge, how many parts survive — and give the conservative figure at 95% confidence." You get back:

At 35.00 mm: 95% confident at least 99.4% of parts survive.

Same idea, the other way round. A height you can't change might turn out to be plenty safe — or to fall short of your target, which is exactly the kind of thing worth finding out before it matters.

The planner — "how many parts would I need?"

The third mode doesn't touch your data's height at all — it answers a planning question before you commit parts: to pin down a given reliability at a given confidence, roughly how many parts should you budget? In the menu this is [3] How many parts do I need?. In one line:

reliability_query(result, 'break', 'plan', 0.999, 0.95)

It replies with a recommended number, a floor, and an honest caveat. The recommended figure is set by how many nines you ask for and how sure you want to be (the reliability and the confidence) — not by your parts' spread — so it is a planning number you can use before you test:

Plan for about 382 parts. This is an estimate; the true number depends on
the real spread, known only after testing.
(Why at least 20: ...large-sample approximation dependable around 20 tests...)
(Counting failures directly would need ~2995 parts.)

Two useful contrasts in that answer:

  • The floor of 20 — below about 20 parts the confidence maths (a large-sample approximation) isn't dependable, results must first overlap for any fit to exist, and the estimates are still settling. So the planner never recommends fewer.
  • The "counting failures directly" number is what you'd need if you just dropped parts and waited to see failures at that reliability — often thousands. This method gets the same answer from a few dozen, because it models the whole curve instead of waiting for rare events. That contrast is a strong point to make to an instructor.

The honest limit: extreme reliabilities need many parts

Asking for 1 in a million (99.9999%) from 25 parts is asking a lot — and the tool will tell you so rather than invent a confident-looking number. Two honest things can happen:

  • The conservative bound comes back "undetermined" (or floored at the 1-in-a-million edge), meaning the thin data can't rule out worse. That's the tool refusing to bluff.
  • The planner recommends a large number of parts — the honest cost of proving a far-tail claim.

This is a feature, not a bug. The all-fire / no-fire edges sit ~3 spreads out on the bell, where the test placed few or no drops; stretching that far is inherently less certain (see Reading your results). The fix is always the same: ask for a reliability you can back up, or print more parts.

One-line summary of the calls

reliability_query(result)                                   % guided menu
reliability_query(result, tail, 'height_for',     R, C)     % Mode A: reliability R -> height
reliability_query(result, tail, 'reliability_at', x, C)     % Mode B: height x -> reliability
reliability_query(result, tail, 'plan',           R, C)     % planner: parts needed for R
%   tail = 'break' or 'survive'
%   R    = reliability as a fraction, e.g. 0.999
%   x    = a height in mm
%   C    = confidence as a fraction, e.g. 0.95 (optional; defaults to the setting)
