How we know the tool is right

"How do you know your program gives the correct answer?" is the first thing a careful reviewer asks. The answer: four separate routes, each built independently, all land on the same result. If any one had a hidden mistake, they would disagree.

Neyer (1994) paper, Table 1  :  mean = 5.39     std dev = 1.04
our tool (Octave 11.3.0)     :  mean = 5.3922   std dev = 1.0412
independent scipy fit        :  mean = 5.3922   std dev = 1.0412
senpy (independent Neyer)    :  mean = 5.3922   std dev = 1.0412

The four routes

1 · The paper — the "answer key." In 1994 Neyer published a real 20-drop experiment: the exact heights, the running estimates, and the final answer (5.39 / 1.04). Fixed in print, made long before us. The ground truth.

2 · Your tool — the thing being tested. Fed the same 20 outcomes, does it choose the same heights and end on the same numbers? Yes — 5.3922 / 1.0412.

3 · scipy — a neutral referee. A standard statistics library, unrelated to our code. Handed only the 20 final data points, it fits the same bell curve independently: 5.3922 / 1.0412.

4 · senpy — an independent copy of the whole method. A separate, community-written package (different authors, Python instead of MATLAB) that implements Neyer's method itself. Given the same data it returns 5.3922 / 1.0412 — confirming not just the arithmetic but the whole procedure, built by someone else entirely.

What each comparison proves

ComparisonWhat it checks
Tool vs PaperWe implemented Neyer's whole procedure faithfully — both the placement (same heights) and the final fit (same numbers).
Tool vs scipyOur fitting arithmetic is correct, confirmed by unrelated code using the same statistical model.
Tool vs senpyThe whole method is correct, confirmed by an independent implementation of Neyer's design in a different language.

Why agreement means confidence

A hidden bug almost always shows up as disagreement. Wrong placement logic → we'd pick different heights than the paper. Wrong fitting maths → we'd disagree with scipy. A subtle error anywhere in the method → we'd disagree with senpy. Four independently-built routes landing on the same answer is strong evidence there is no hidden error.

Earlier we noted a caveat — that scipy uses the same statistical model as our tool, so it only checks the arithmetic, not the whole idea. senpy closes that gap: it's a genuinely independent implementation of the full Neyer method by other authors, and it agrees too. So both the arithmetic and the whole procedure are independently confirmed. (senpy and gonogo are the two free reference implementations of the family.)
One line for your instructor: "I validated it four ways — my tool reproduces Neyer's published example exactly (both the test sequence and the answer), an independent statistics library fits the same data to the same mean and standard deviation, and a separate community-written implementation of Neyer's method returns the same result in a different language. Procedure and arithmetic are both independently confirmed."
